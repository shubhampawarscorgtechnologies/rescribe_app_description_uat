Consultation Chart components are configurable. Which sections appear inside the chart is set in the web application, drawn from: Vitals, Score Templates, Complaints, Diagnosis, Growth Chart, Advice, Allergies, Follow-up Date & Time, Pain Scale, Image Annotations, Investigation, Medicine, Examination.

Two hospitals on the same build can therefore show different tabs and different chart sections. Always confirm a site's configuration before treating a missing section as a defect.

1.3 Investigation History — the three parts

This same three-part view appears in several places (Facesheet, the Investigation option, Appointment List, Search). It always means the same thing.

PartContains
HistoryWhat was ordered and when — X-ray, CT scan, CBC and so on.
ReportsThe result documents returned by LIS (lab) and RIS (radiology).
LIS listThe lab investigations themselves and their individual line items.

Editable vital sheets covering both routine vitals and ventilator parameters, so ICU patients are recorded on the same screen as ward patients.

Paperless documentation for the admitted patient — writing on documents by hand instead of on paper. The feature is identical on the nurse side and is documented separately in the Paperless Documentation map.

Requirement for online consultation: calling and messaging work only if the patient has the Rescribe Patient App installed and registered. If the patient has not installed it, the call cannot connect — this is the single most common "calling is not working" report, and it is not a fault on the doctor's device.

TabContainsWhat it is for

This is how documentation gets completed late. A doctor who could not finish writing during the visit opens Search → Visit List → the visit → Pen Mode, and adds or edits the documents afterwards. Nothing is lost because the consultation has ended.

Important sequence — the same rule as the nurse app.

Check View Sync Pending Offline Data before using Clear Cache or Logout. If the list is not empty, the device still holds work that has not reached the server. Get back on network and let it sync first.

Parts of this app are assembled per hospital in the web application. The same build therefore looks different at different sites — by design, not by fault.

In practice

A typical day, in order

The same features, arranged the way a doctor actually meets them. This sequence is what a demo or a training session should follow.

  1. Open the app and set the branchMain screen — select branch, read the dashboard.
  2. Ward roundAdmitted Patient card → patient → Facesheet for history, Vitals to record, Orders to prescribe.
  3. Write at the bedsidePen Mode — handwrite on the document instead of on paper.
  4. Start the consulting sessionToday's Appointment — work down the list, update status as each patient is seen.
  5. See online patientsVideo or audio call from the same list; message if a call is not needed.
  6. Look up anyone not on the listSearch → Patient List, then Visit History or Investigation History.
  7. Finish yesterday's paperworkSearch → Visit List → the visit → Pen Mode.
  8. Close the dayMenu — confirm no pending offline data, then log out.
